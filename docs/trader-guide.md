# 모의투자 실행기 사용법

## 1. 연습 모드로 먼저 돌려보기 (키움 없이)
```
python scripts/run_trader.py --check     # 주문 계획만 보기
python scripts/run_trader.py             # 가상 계좌(1만 달러)로 실제처럼 기록
```
결과는 `paper/` 폴더에 쌓입니다.

## 2. 키움 모의투자로 실행
```
python scripts/run_trader.py --mode kiwoom --check   # 잔고·예수금만 조회하고 주문 계획 출력
python scripts/run_trader.py --mode kiwoom           # 실제 모의 주문
```
- `--check`는 주문을 내지 않고 잔고(ust21070)와 예수금(ust21160)만 읽습니다. 처음엔 꼭 이것부터 실행하세요.
- 주문은 지정가(ust20000 매수, ust20001 매도)로 나갑니다. 키움 모의투자는 시장가를 받지 않아서, 매수는 현재가보다 1.5% 높게, 매도는 1.5% 낮게 값을 불러 바로 체결되게 합니다. 미국장이 열려 있을 때만 체결됩니다.
- 키움은 주문을 받기만 하고 체결은 나중에 되므로 `trades.jsonl`에는 `pending`으로 기록됩니다. 다음 실행 때 잔고에서 실제 보유수량을 다시 읽습니다.
- 매도 대금이 아직 정산 전이라 같은 날 매수가 "예수금 부족"으로 거부될 수 있습니다. 그러면 그달 리밸런싱이 끝나지 않은 것으로 남고, 다음 날 실행 때 부족한 만큼만 다시 주문합니다.

## 3. Mintory 앱 (더블클릭 한 번)
`mintory.bat`(또는 바탕화면 Mintory 아이콘)을 열면 세 가지가 일어납니다.
1. 창 없이 뒤에서 도는 **자동 실행기**가 켜집니다(이미 켜져 있으면 그대로).
2. Mintory 창이 열리고, 키움 모의계좌 잔고를 새로 읽어 화면을 갱신합니다. 이때는 주문을 절대 내지 않습니다.
3. 윈도우를 켤 때 자동 실행기가 저절로 켜지도록 등록합니다.

**로고 옆 시장 지수**: S&P 500, 나스닥, VIX(공포지수)의 현재값과 오늘 등락률, 오늘 하루 미니 그래프가 보입니다. 장중에는 15초마다, 장이 닫혀 있으면 10분마다 새로 받습니다(야후 파이낸스, 화면 표시용).

**미국장 시계**: 지수 옆에 지금 미국장 상태(정규장·프리마켓·애프터마켓·장 마감·주말 휴장)와 마감 또는 개장까지 남은 시간, 그 시각(한국시간)이 보입니다. 정규장 중에는 아래 막대가 차오릅니다. 미국 공휴일은 반영하지 않아요.

**상태 불** (버튼 왼쪽 작은 불): 🟢 정상, 🟡 일시정지 중, 🔴 확인 필요(자동 실행 실패·놓침, 오류, 며칠째 기록 갱신 없음). 누르면 모드, 다음 자동 실행, 마지막 실행, 기록 업데이트·백업 시각과 문제 내용이 펼쳐집니다.

화면 오른쪽 위 버튼:
- **잔고 새로고침**: 키움 모의계좌 잔고를 다시 읽습니다. 주문은 내지 않습니다.
- **지금 매매 실행**: 밤 11시 45분 자동 실행과 같은 작업을 지금 한 번 합니다. 확인창이 먼저 뜨고, 미국장이 닫혀 있으면 그 안내도 보여줍니다.
- **일시정지 / 다시 시작**: 일시정지하면 그 뒤로 주문을 내지 않습니다(자동 실행 포함). 상태 불이 노란색으로 바뀝니다.

**실시간 시세**: 미국장이 열려 있는 동안(한국 밤 10시 반~새벽 5시, 서머타임이 끝나면 한 시간 늦게) 보유 종목의 현재가, 오늘 등락률, 손익, 총 평가금액, 수익률 그래프의 "지금" 점이 15초마다 바뀝니다. 가격이 오르면 빨갛게, 내리면 파랗게 잠깐 깜빡이고, 총 평가금액 옆에 "● 실시간"이 뜹니다. 창이 넓으면(가로 1880px 이상) 종목마다 오늘 하루 미니 그래프도 보입니다. 시세는 야후 파이낸스에서 받아 몇 초~1분 늦을 수 있고, 화면 표시용일 뿐 주문에는 쓰지 않습니다. 장이 닫혀 있으면 "장 마감"으로 표시하고 마지막 가격을 보여줍니다.

**자세히 보기**: 보유 종목, 수익률, 매매 내역 칸 오른쪽 위의 **자세히** 버튼을 누르면 큰 표가 열립니다. 머리글을 누르면 그 항목으로 정렬되고, Esc 나 닫기로 닫습니다.
- 보유 종목: 종목별 수량, 평균단가, 현재가, 매입금액, 평가금액, 비중(목표), 손익, 오늘 손익, 수수료, 첫 매수일
- 수익률: 누적 수익률, SPY 대비, 최대 낙폭, 가장 좋은/나쁜 날 요약과 날짜별 평가금액·하루 손익·누적 수익률·낙폭
- 월별 결산(수익률 칸의 **월별 결산** 버튼): 월말 잔고 추이 그래프와 달마다 손익 막대(빨강 수익, 파랑 손실), 월별 월초·월말 잔고, 손익, 수익률, SPY 대비, 월중 최대 낙폭, 매매 건수, 수수료, 연도별·전체 합계
- 매매 내역: 모든 주문의 시각, 수량, 체결가, 금액, 수수료, 상태, 바구니, 메모(주문번호·거부 사유)와 매수/매도 합계

화면은 자동 실행기가 `http://127.0.0.1:47321` 에서 보여줍니다. 이 주소는 내 PC 안에서만 열리고, 다른 웹사이트가 버튼을 대신 누를 수 없게 막혀 있습니다.

### 다음 리밸런싱 미리보기
오른쪽 **다음 리밸런싱** 칸에 다음 주문일의 예상 주문이 나옵니다(빨강 매수, 파랑 매도). 지금 가격이 신호일까지 그대로라고 가정하고 계산한 것이라, 실제 주문은 신호일 장 마감 가격으로 다시 계산되어 수량이 조금 달라질 수 있어요. 잔고 새로고침이나 자동 실행 때마다 새로 계산합니다.

### 백테스트 비교
수익률 그래프의 보라색 점선이 **백테스트**입니다. 같은 전략을 첫 기록일의 평가금액으로 시작해, 장 마감 가격에 사고팔았다고 계산한 값이에요(모의투자 수수료 0.25% 가정). 실제 선(흰색)과 차이가 작으면 실행기가 백테스트대로 잘 돌고 있다는 뜻입니다. "수익률 자세히"에서 날마다 "백테스트 대비" 차이를 볼 수 있어요.
- 차이가 생기는 이유: 실제 주문은 밤 11시 45분(장중) 지정가로 나가고, 백테스트는 장 마감 가격을 씁니다. 수수료, 정수 주식 수, 현금 2% 여유분 차이도 조금씩 쌓입니다.
- 차이가 계속 한쪽으로 커지면(예: 한 달에 -3%p 이상) 주문이나 체결에 문제가 있는지 살펴볼 신호입니다.

### 실계좌 점검
Mintory 위쪽의 **실계좌 점검** 버튼(또는 텔레그램 `/check`)을 누르면 실계좌로 바꾸기 전에 확인할 것들을 한 장으로 보여줍니다. ✅ 준비됨, ⚠️ 확인 권장, ❌ 꼭 고쳐야 함, ⬜ 아직 확인 안 함.
- 모의투자 기간(20거래일 이상), 백테스트와의 차이(±3%p 안), 자동 실행 실패·놓친 날, 최근 30일 거부·미체결 주문
- 텔레그램 연결, 주문 한도(`MAX_ORDER_USD`), 하루 손실 한도, PC 깨우기 작업, 일시정지 여부
- 실계좌 앱키: 키움에서 **실전투자용 앱키를 모의투자 키와 따로** 발급받아 `.env` 의 `KIWOOM_LIVE_APP_KEY`, `KIWOOM_LIVE_SECRET_KEY` 에 넣습니다. 점검 창의 **실계좌 키 확인 (조회만)** 을 누르면 실계좌 서버에서 달러 예수금만 조회해 키가 맞는지 봅니다.

점검표는 **보기만** 합니다. 주문을 내지 않고, 자동 매매를 실계좌로 바꾸지도 않습니다. 실계좌 전환은 모든 항목을 확인한 뒤 따로 진행합니다.

## 4. 매일 자동 실행 (앱이 알아서)
- 자동 실행기는 **한국시간 월~금 밤 11시 45분**에 모의투자를 실행합니다. 미국장은 밤 10시 30분(서머타임) 또는 11시 30분에 열리므로 두 경우 모두 장중입니다.
- 기본 전략(2026-10-10부터)은 **EEM 카나리아 + 4분할**입니다. 돈을 4덩어리로 나눠 월말, +5, +10, +15거래일에 한 덩어리씩 리밸런싱하므로 한 달에 최대 4번 주문합니다. 리밸런싱 날 신흥국 ETF(EEM)의 모멘텀이 0 이하면 그 덩어리는 전부 IEF(중기 국채)로 피합니다. 목표가 바뀐 날에만 주문하고, 나머지 날은 평가금액을 기록하고 대시보드를 새로 만듭니다.
- 예전 전략(월 1회 멀티기간 모멘텀)은 `--strategy multi`로 쓸 수 있습니다.
- 전략이 바뀌면 첫 실행 때 이전 기록(`trades.jsonl`, `equity.jsonl`, `meta.json`)을 `paper/archive/<이전 전략>_<날짜>/`로 옮기고 그날부터 수익률을 새로 셉니다. 보유 종목은 그대로 두고 새 목표와 차이나는 만큼만 사고팝니다.
- 11시 45분에 PC가 꺼져 있었더라도 새벽 5시 전에 켜면 바로 실행합니다. 그보다 늦으면 다음 날 실행에서 밀린 리밸런싱을 처리합니다.
- **놓친 매매 대비**
  - Mintory를 열면 윈도우 작업 스케줄러에 `Mintory 자동 실행` 작업이 등록됩니다. 평일 밤 11시 40분에 PC가 잠자기 상태면 깨워서 실행기를 켭니다. (전원이 완전히 꺼진 PC는 깨울 수 없습니다. 노트북은 전원을 연결해 두세요.)
  - 실행 20분 전부터 실행이 끝날 때까지는 PC가 저절로 잠들지 않게 붙잡습니다. 노트북 덮개를 닫으면 그래도 잠듭니다.
  - 그래도 놓친 밤이 있으면 휴대폰(텔레그램)으로 알리고, Mintory 상태 불이 빨간색으로 바뀝니다(눌러 보면 놓친 날짜가 나와요). 밀린 주문은 다음 자동 실행 때 목표 비중과 비교해 알아서 맞춥니다.
  - 깨우기가 안 되면: 제어판 > 전원 옵션 > 고급 전원 관리 옵션 > 절전 > **절전 모드 해제 타이머 허용**을 "사용"으로 바꿔 주세요.
- 상태는 `paper/agent.json`(다음 실행 시각, 마지막 결과), 기록은 `paper/logs/agent.log`에 남습니다.
- 다음 실행 시각 확인: `py scripts/mintory_agent.py --status`
- 윈도우 시작 시 자동 실행과 깨우기 작업 해제: `py scripts/mintory_agent.py --uninstall-startup`

## 5. 업데이트 (update.bat 더블클릭)
`update.bat`을 더블클릭하면 GitHub의 최신 코드를 받아 이 폴더에 덮어씁니다. ZIP을 받아 `.env`와 `paper` 폴더를 옮겨 붙일 필요가 없습니다.
- `.env`, `paper/`(매매 기록), `reports/`, `data_cache/`는 건드리지 않습니다.
- 처음 한 번은 GitHub 읽기 전용 토큰이 필요합니다. 없으면 만드는 방법이 화면에 나오고 GitHub 페이지가 열립니다. 만든 토큰은 `.env`에 `GITHUB_TOKEN=...` 한 줄로 넣습니다.
- 자동 실행기가 매매 중이면 업데이트하지 않습니다. 켜져 있으면 1분 안에 새 코드로 스스로 다시 켜집니다.
- 새 버전이 있는지만 보기: `python scripts/update.py --check`

## 6. 휴대폰 알림 (텔레그램)
`notify_setup.bat`을 더블클릭하면 화면 안내대로 텔레그램 봇을 만들고 연결합니다(처음 한 번). 연결되면 휴대폰으로 이런 알림이 옵니다.
- 주문이 나갔을 때: 종목, 수량, 체결/거부
- 문제가 생겼을 때: 실행 실패, 계좌 조회 실패, 오래된 가격 데이터, 일시정지 중이라 주문 안 함
- 매일 밤 자동 실행 후 평가금액·오늘 수익률·누적 수익률 한 줄 요약 (끄려면 `.env`에 `NOTIFY_DAILY=0`)
- **주간 리포트**: 토요일 아침 7시(금요일 미국장 마감 뒤)에 잔고를 마감 가격으로 새로 불러와서 이번 주 수익, SPY·백테스트와의 비교, 이번 주 매매와 수수료, 다음 리밸런싱 날짜를 보냅니다. 그 시각에 PC가 꺼져 있었으면 주말 중 켜질 때 보냅니다. (끄려면 `.env`에 `NOTIFY_WEEKLY=0`)

- **리밸런싱 미리 알림**: 리밸런싱 주문 전날 밤 자동 실행이 끝나면 다음 날 나갈 예상 주문(종목·수량·금액)을 먼저 보냅니다. 바뀌는 종목이 없으면 보내지 않아요. (끄려면 `.env`에 `NOTIFY_PREVIEW=0`)

시험 알림만 다시 보내기: `py scripts/notify_setup.py --test`. 알림이 실패해도 매매에는 영향이 없습니다.

**휴대폰 명령.** Mintory 자동 실행기가 켜져 있는 동안 봇 대화방에 아래 명령을 보내면 답합니다. 대화방 입력칸 옆 메뉴(/) 버튼에도 나옵니다. 한국어로 `잔고`, `일시정지`처럼 보내도 됩니다.

| 명령 | 하는 일 |
|---|---|
| `/balance` (잔고) | 보유 종목, 평가금액, 누적 수익률. 최신 시세가 있으면 그 값으로 계산 |
| `/refresh` (새로고침) | 키움 잔고를 새로 불러온 뒤 잔고 보내기 (주문 없음) |
| `/status` (상태) | 다음 자동 실행, 마지막 실행 결과, 다음 리밸런싱, 일시정지 여부 |
| `/next` (다음) | 다음 리밸런싱 날짜와 지금 가격 기준 예상 주문 |
| `/check` (점검) | 실계좌 전환 점검표 (아래 '실계좌 점검' 참고) |
| `/pause` (일시정지) | 자동 매매가 주문을 내지 않게 멈춤 (Mintory의 일시정지 버튼과 같음) |
| `/resume` (재개) | 다시 주문 |
| `/help` (`/?`, 도움말) | 명령 목록 |

- 연결한 본인 대화방의 메시지만 따르고, 다른 사람이 봇에 보낸 메시지는 무시합니다.
- 주문을 내는 명령은 일부러 만들지 않았습니다.
- PC가 꺼져 있는 동안 보낸 명령은 10분이 지나면 버립니다(나중에 켜졌을 때 뒤늦게 일시정지되는 일 방지).

## 7. 기록 백업
Mintory 자동 실행기가 매일 아침 7시(미국장 마감 뒤)에 `paper` 폴더(잔고·매매·수익 기록)를 `backups\paper-날짜.zip` 으로 한 부씩 저장합니다. 최근 60개만 남깁니다. PC가 꺼져 있었으면 켜진 뒤 그날 것을 만듭니다.
- PC 디스크가 고장 나는 경우까지 대비하려면 `.env` 의 `BACKUP_DIR=` 에 OneDrive 같은 다른 폴더를 적으세요. 거기에도 한 부씩 복사합니다.
- 마지막 백업 날짜는 텔레그램 `/status` 와 실계좌 점검표에 나옵니다.
- 되돌리기: 먼저 Mintory에서 **일시정지**를 누르고, 명령 프롬프트에서
  - `py scripts/restore_backup.py` → 백업 목록
  - `py scripts/restore_backup.py 2026-10-12` → 그날 기록으로 되돌리기 (지금 기록은 오늘 날짜 백업으로 먼저 저장하니, 잘못 골라도 다시 돌아올 수 있어요)

## 8. 긴급 정지
Mintory 화면의 **일시정지** 버튼을 누르세요. 화면을 열 수 없을 때는 `paper` 폴더에 `STOP`이라는 이름의 빈 파일을 만들어도 똑같습니다. 파일을 지우면(또는 다시 시작 버튼) 다시 동작합니다.

## 안전장치
- **주문 한도**: 주문 하나가 한도를 넘으면 그날 주문을 전부 막고 알림을 보냅니다. 기본 한도는 계좌 전체 금액이고(가격·단위 계산 오류 대비), `.env` 의 `MAX_ORDER_USD=50000` 처럼 달러 금액으로 정할 수 있습니다. **실계좌는 이 값을 정해야만 주문이 나갑니다.**
- **하루 손실 한도**: 계좌가 전날 장 마감보다 10% 넘게 빠져 있으면 그날은 주문하지 않고 텔레그램으로 알려줍니다. 다음 날 다시 확인합니다. `.env` 의 `MAX_DAILY_LOSS_PCT=8` 처럼 바꾸거나 `0` 으로 끌 수 있습니다.
- **실계좌 주문 알림**: 실계좌로 바꾼 뒤에는 주문을 보내기 직전에 종목·수량·금액을 텔레그램으로 먼저 보냅니다(확인 단계 없이 바로 주문). 모의투자에서는 이 알림이 없고, 실행이 끝난 뒤 결과 알림만 옵니다.
- 50달러 미만의 자잘한 조정 주문은 건너뜁니다.
- 현금 2%는 수수료와 가격 변동에 대비해 남겨둡니다.
- 같은 달에는 리밸런싱을 한 번만 합니다. 주문이 하나라도 실패하면 다음 실행 때 다시 시도합니다.
